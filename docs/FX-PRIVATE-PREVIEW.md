# Currency rates in the private VPS preview

The storefront browser reads `/api/shop/rates/` on its own origin. The Node server reads Nobitex `usdt-rls` market statistics and a validated USD exchange-rate feed. Currency API is the primary free feed, fetched through its jsDelivr and Cloudflare mirrors; Coinbase is a last fallback. No API key, trading request, wallet connection or payment is involved.

- Nobitex `latest` is in rial; divide by ten for Toman. A closed or invalid market is rejected.
- Rates are units per USD. Multiply USDT/Toman by USDT-per-USD to derive USD/Toman. This is a derived rate, not a cash-dollar quote, and USDT is not assumed to equal USD or USDC.
- Nobitex and the chosen FX feed cache independently for one minute, coalesce concurrent requests, and retry failed requests after thirty seconds. Validated daily mirrors race with six-second deadlines; Coinbase gets three seconds only if both fail. The combined upstream budget is at most nine seconds, below the eleven-second browser deadline. The last validated source value remains visible after a failed refresh.
- Currency API observations update daily. Their ISO date, provider and selected mirror are carried separately from retrieval time. Future dates, impossible dates, missing rates and observations from two or more UTC calendar days ago are rejected. A freshly downloaded old observation never becomes valid again. No USD/USDT peg is assumed.
- Each source has its own retrieval time and status. The combined snapshot uses the older retrieval time. A failed refresh never renews it. Neither feed supplies an individual trade timestamp in the fields used here. The daily source date is shown on the rates page and frozen into saved simulated invoices.
- Foreign pricing and simulated checkout require rates less than fifteen minutes old and a successfully loaded store policy. A missing FX source can leave the USDT card usable while foreign conversion is unavailable. Quote expiry is capped by both retrieval freshness and the daily observation expiry.
- Explicit sample mode applies only to the current mounted test screen. It never overwrites the real-rate cache. Reloading or navigating always returns to market sources, and legacy cached samples are discarded without clearing carts, orders or store policies. Choosing Market rates clears sample values immediately; a failed fetch cannot leave the fictional value displayed as a fallback. A live response in flight cannot silently replace a newly chosen sample.
- Country selection changes product and cart currency, keeping quantities unchanged. Supported mappings: Iran/Toman, Turkey/TRY, UAE/AED, Germany/EUR, UK/GBP, US/USD, Canada/CAD, Other/USD.
- The rates page converts a typed Toman amount and shows the selected country's configured service fee separately. It uses the same integer rounding and fee calculation as the cart, with zero discount and delivery. Persian and Arabic digits are accepted. Amounts that round below the selected currency’s smallest unit show an input message instead of throwing or creating a zero-value quote.
- Store policy remains shared through the existing database-backed admin settings, with country overrides and optimistic concurrency. No schema migration or reset is required.

The update installer only changes `roya-preview.service` on `127.0.0.1:3311`. It validates the previous source and release, builds before stopping the preview, retains the old release, backs up its environment and unit, switches the release symlink and checks health/access/live-effect guards. A failed switch check restores the previous preview. It prints a private rollback command. The existing backend and Nginx configuration are preserved. This configuration backup does not replace the database backup task.

Validation: 51 domain tests and 30 server tests; production build and TypeScript; the local production HTTP endpoint returned validated rates from both live providers and preserved admin/payment/SMS guards. Browser checks use controlled rate and policy fixtures to exercise FA/EN, country conversion, fees, quantity preservation, partial-source failure, stale-rate blocking, legacy sample-cache migration, offline sample eviction, real-cache preservation and returning from explicit sample mode after reload. Actual VPS source connectivity and administrator persistence still require validation on the VPS after installation.
