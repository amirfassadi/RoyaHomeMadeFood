# پاک‌سازی فایل‌های اضافی رویا در پوشهٔ امیر

درخواست اپراتور در ۲۰۲۶-۱۰-۲۵: بررسی حجم و حذف موارد اضافی‌ای که خودمان برای رویا ساخته‌ایم، فقط در پوشه‌های امیر. وضعیت این ثبت: گزارش آماده است؛ هیچ فایلی هنوز حذف نشده و عدد فضای آزادشده نداریم.

## مبنا و محدوده

پشتیبان تازه با تست restore جداگانه تأیید شده است: /var/backups/roya/pre-admin-20261025T113855Z-3a36bd50. runtime آخرین گزارش همچنان 321f8929648c9fcf2bdcfda3e270352b0b9d2174 است. marker و مسیر فرایند/سرویس در گزارش امروز دوباره خوانده می‌شوند؛ نصب جدیدی از این مستندات نتیجه گرفته نمی‌شود.

گزارش قدیمی پوشه‌های ساخت حدود ۱٫۲ گیگابایتی را نشان می‌داد؛ اندازهٔ امروز باید از inventory دریافت شود. کد، package-lock و اسکریپت‌های بازیابی کوچک‌اند و حذف آن‌ها برای آزادکردن فضای اصلی لازم نیست.

## موارد محافظت‌شده

- برنامه‌های نصب‌شده و releaseهای /opt/roya، تمام پشتیبان‌های /var/backups/roya و تنظیمات /etc دست‌نخورده می‌مانند.
- کش /home/amir/.npm و /home/amir/.cache/Prisma به‌دلیل اختلال اتصال خارجی حفظ می‌شوند؛ دست‌کم یک کپی مناسب از وابستگی‌های نصب‌شده هم باید باقی بماند.
- ساخت standalone آماده، کاندید نصب/بازگشت و مسیرهای cwd سرویس/فرایند فعال پیش از هر حذف شناسایی و حفظ می‌شوند.
- پوشه‌های پروژه‌های دیگر، کلیدهای SSH، فایل‌های env، دیتابیس، رسانه/اطلاعات خصوصی و سورس/اسکریپت‌های نگهداری حذف نمی‌شوند.

## مراحل مجاز

۱. inventory فقط‌خواندنی: یک du از home امیر، تفکیک Roya setup و خروجی‌های node_modules/.next/.roya-domain-stage، شناسهٔ قفل وابستگی‌ها و markerهای نسخه، وضعیت مسیر سرویس و فرایندها و رسید پشتیبان.
۲. انتخاب مسیرهای دقیق و تکراریِ متعلق به رویا بر اساس همان گزارش؛ حجم بالای کل home مجوز حذف پروژهٔ دیگر نیست. صورت‌حساب du، تخمین فضاست و جمع‌زدن داده‌های دارای hard link لزوماً فضای قابل آزادسازی نمی‌دهد.
۳. حذف فقط پس از کنترل دوبارهٔ نسخه/قفل، محدودهٔ واقعی path و mount/symlink، نبود وابستگی فعال و وجود نسخهٔ نگه‌داشته‌شده. مجوز پاک‌سازی این موارد از درخواست امیر آمده است؛ تأیید تکراری برای همان محدوده لازم نیست.
۴. ثبت فهرست واقعی حذف، df پس از کار، حفظ marker و سلامت محلی HTTPS/ادمین. صرف نوشتن طرح یا جابه‌جایی فایل‌ها به معنی آزادشدن فضا نیست.

گزارش deploy/inspect-amir-disk.py هیچ فایل/env محرمانه یا argv فرایند را نمی‌خواند؛ JSONهای package/descriptor و رسید پشتیبان فقط برای metadata لازم استفاده می‌شوند. این ابزار source عمومیِ وابسته به Git است؛ دادهٔ واقعی inventory فقط از VPS اپراتور معتبر خواهد بود.
